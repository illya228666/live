Возможность согреться и уйти от перегрева сохраняется на всём периоде.

## Пассивность и активная разрешимость

Для любого фиксированного места аналитическая граница неизбежного пикового
отклонения тела — **не менее 3.81 °C**, включая поправку на дискретное время.
Это проверка всех постоянных мест, а не только случайных стартов. Дополнительная
сетка 10 001 радиуса даёт лучшую стационарную долю комфорта **41.47%**;
лучший MAE среди фиксированных радиусов — **2.076 °C**. Эти два лучших радиуса
не обязаны совпадать. Переходный процесс не устраняет периодические нарушения.

Реальный RuntimeSession: пять новых seed, по 4 000 шагов и четыре стратегии,
без обучения. Средние по seed; все стартовые шаги включены.

| Стратегия | Комфорт, % | MAE, °C | Доля шагов с движением, % |
|---|---:|---:|---:|
| Не двигаться со старта | 2.835 | 5.3926 | 0 |
| Дойти до приближения лучшего постоянного места и остаться | 31.250 | 2.2381 | 0.280 |
| Случайные допустимые действия | 5.775 | 6.0338 | 88.955 |
| Обратная связь по локальным температурным сенсорам | **99.855** | **0.0311** | **56.445** |

Худшая доля комфорта активного контроля среди пяти seed — **99.725%**, выше
заранее заданных 90%; MAE каждого seed ниже 0.5 °C. Контроллер получает только
существующие токены тела и пяти локальных сенсоров, а не будущую фазу огня,
глобальную карту или reward. Это свидетельство достижимости задачи, а не
результат обучения DQN и не кандидат для объявления научного победителя.

Проверка повторена отдельным запуском: совпали все 20 последовательностей
действий по SHA256 и числовые результаты. Старый тепловой вариант также прогнан
как отрицательный контроль: аудит его отверг из-за пригодного постоянного места.

Полные проверочные данные: [JSON](temperature-scenario-v2-results.json).
Raw calibration/verification/repeat/legacy-rejection:
`artifacts/scenario-audits`. Прежние конфигурации и опубликованные результаты
оставлены историческими; исправленная среда не подставляется в старые отчёты.

## Правило для всех факторов

Новые научные pilot/full в research.ps1 требуют passing suitability review
для всех активных факторов. Проверяются fingerprint общих физических условий,
профиль оценки, горизонт и SHA256 доказательств; настройки мотивации, learner и
обучающий бюджет не меняют этот fingerprint. Review и доказательство копируются
в study и повторно проверяются перед вычислениями.

Если фактор тривиален или неразрешим для разумного активного контроля, нужно
**исправить параметры общего сценария и повторить аудит**. Caveat в отчёте
не даёт допуска. `diagnostic` позволяет исследовать дефект, но не ранжировать
подходы как будто задача валидна. Для факторов без drive-ключа исследователь
обязан явно добавить содержательный review; автоматическая проверка не заменяет
осмысление задачи.

Текущая база проверена **только для температуры**. Голод, угрозы и их сочетания
потребуют самостоятельных пассивных/активных и совместных проверок до включения
в научное сравнение. Метрика близости кабана остаётся прокси, а не ущербом.

## Повторить

```powershell
. ./tools/common.ps1
Initialize-Dotnet
Invoke-Dotnet build src/ArtificialLife.Cli -c Release
Invoke-Dotnet run --project src/ArtificialLife.Cli -c Release --no-build -- scenario-audit --config configs/research-baseline.json --protocol configs/research-baseline-validation.json --output artifacts/scenario-audits/new-check
Invoke-Dotnet run --project src/ArtificialLife.Cli -c Release --no-build -- scenario-validate-review --config configs/research-baseline.json --review research/scenarios/temperature-v2-review.json
```

Новый аудит сохранять в новый каталог; не перезаписывать неудачные проверки.

Неизменные DLL сделаны независимыми от Git SHA в отладочных метаданных сборки:
это предотвращает ложную инвалидизацию baseline после коммита заметок. Git revision,
diff и исходники по-прежнему сохраняются в provenance. Принудительная пересборка с
другим SourceRevisionId дала те же SHA256 Core/Temperature. Контроли до и после
этой настройки также совпали по всем действиям и числам; физика не менялась.

Проверки реализации: **163 теста прошли**. Дополнительно проверены реальная
регистрация исправленной базы, отказ регистрации старого тривиального варианта
и отказ исполнения при изменении сохранённого review. Эти admission-проверки
не запускали обучение. Краткий машинный аудит:
`research/scenarios/temperature-v2-validation.json`.
