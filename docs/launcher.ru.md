# Launcher: отдельные World Host и Viewer

Соберите решение Release и Godot-проект Debug штатным локальным SDK.
В Visual Studio выберите ArtificialLife.Launcher запускаемым проектом и нажмите F5;
в VS Code используйте существующий профиль лаунчера. Bootstrap готовит закреплённые
SDK/Godot, а пакеты нужно подготовить до запуска мира.

## Режимы

- **Открыть независимый Viewer** — выбор уже работающего мира, без запуска симуляции.
- **World Only** — мир без агента и контроллера; конфигурация `configs/world-only.json`.
- **Inference** — готовая политика из checkpoint действует без обучения.
- **Live Training** — новая непрерывная обучающая жизнь в отдельном Worker.
- **Evaluation** — фиксированная политика и заданный бюджет шагов, без внешнего вмешательства.

Флажок подключения Viewer запускает его отдельным процессом после создания мира.
Для нескольких независимых миров запустите несколько конфигураций: каждому запуску
Launcher создаёт собственный каталог. Кнопка обновления показывает локальные сессии;
выбранную сессию можно открыть в Viewer или явно остановить, если режим разрешает.
Закрытие Launcher или Viewer не останавливает Host.

## Управление Viewer

Колесо меняет масштаб, средняя кнопка перемещает камеру, клик выбирает объект
для просмотра компонентов. F12 сохраняет PNG; рядом записываются возраст,
ревизия, сессия, epoch и номер фактически показанного снимка.

В интерактивных режимах: Пробел — пауза; +/− или 1–4 — скорости
1×/10×/100×/Max; S — checkpoint. R перезапускает мир в World Only/Inference;
Ctrl+Shift+R начинает новую обучающую жизнь. E создаёт отдельную frozen evaluation
и переключает Viewer на неё; повторное E возвращает к приостановленному обучению.
Research и Evaluation могут запрещать команды: это проверяет Host.

Policy checkpoint сохраняет модель для inference, без optimizer/replay. Для warm
start обучения используйте новый каталог запуска и существующую политику;
аварийно потерянное обучающее состояние не выдаётся за точное продолжение.

Полный CLI, протокол и авторство визуальных модулей описаны в
[архитектуре Runtime/Observation](observation-runtime.md).
